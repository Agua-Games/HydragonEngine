# Obsolete code

Files here are kept for reference and history only. **Nothing in this folder is imported, built or
shipped.**

## Why this folder is at the extension root

`source/extensions/hydragon.editor.core/premake5.lua` links whole top-level folders into the build:

```lua
repo_build.prebuild_link {
    { "config", ext.target_dir.."/config" },
    { "hydragon", ext.target_dir.."/hydragon" },
    { "data", ext.target_dir.."/data" },
}
```

The link is per **top-level folder**, and it is recursive. An `obsolete/` folder placed inside
`hydragon/` would therefore be copied into `_build/…/exts/hydragon.editor.core/hydragon/…` and end up
in release packages. At the extension root it is versioned by git - so the history and the reasoning
survive - and never reaches the build output.

## `volume_viewport_manipulator_obsolete.py`

The `omni.ui.scene` wireframe overlay that drew Force and Kill volume bounds, plus its pytest suite.

**Retired 2026-09-11.** Replaced by USD geometry authored into the stage, so that the volumes travel
with the `.usda` and are visible and pickable in any application that opens it:

| role | prim | authored by |
|---|---|---|
| the visual | `volumes/<type>_bounds`, `BasisCurves`, `purpose = "default"` | `volume_triggers.ensure_wireframe()` |
| the physics | `volumes/<type>_trigger`, `Cube`/`Sphere`/`Cylinder`, `purpose = "guide"` | `volume_triggers.ensure_trigger()` |

What the overlay did and what replaced it:

| overlay | replacement |
|---|---|
| `sc.Line` cage, drawn in its own composition pass | `BasisCurves` in the stage, generated by `volume_geometry` |
| picked via a gesture plus a 0.5 s bounded selection-override window, because the wireframe was not geometry | the `BasisCurves` are ordinary geometry, so the native pick selects them directly |
| `Shift+V` hotkey, viewport menu item, persistent setting | moved to `volume_triggers.VolumeDisplayToggle`, which authors `visibility` on the wireframes in the session layer |
| `generate_shape_wireframe_segments()`, its own shape maths | `volume_geometry.build_shape_geometry()`, schema-valid by construction |

Note that the selection-override window was correct and hard-won - it was verified in a live session
and it fixed a real defect. It became unnecessary rather than wrong: once the bounds are real
geometry, there is no pick to override.

Do not revive it for the visual. If the geometry ever needs to be drawn again from Python, start from
`volume_geometry` so that there remains exactly one source of truth for a volume's shape.
